# 她火实时进度控制台与二次精剪架构设计规格

日期：2026-06-19
项目：她火本地提示词中心 / 视频工厂
范围：视频工厂运行可视化、任务日志、基础剪辑到二次精剪的三层剪辑架构

## 背景

当前视频工厂已经具备从文案、分镜、火柴人生图、本地 IndexTTS2 音色克隆、字幕对齐到剪映草稿导入的主链路。这个链路可以完成基础剪辑，但用户在等待生成时仍然不清楚软件正在做什么、卡在哪一步、失败后是否自动切换备用 API、哪些素材已经保留、下一步是否还会继续。

同时，现有剪辑能力更接近“一次加工”：把脚本、图片、配音和字幕按时间线排好，导入可编辑剪映草稿。后续要达到“二次加工 / 精剪”，需要让 AI 输出更细的剪辑决策，再由剪映或 DaVinci 适配器转换为对应项目，而不是让每个引擎各自长出一套互不兼容的逻辑。

本规格把两个方向合并设计：

1. 软件内部实时进度控制台：让用户像看 Codex 执行一样，在她火界面里看到每一步正在干什么。
2. 三层剪辑架构：基础剪辑层、二次加工层、引擎适配层，逐步从稳定可编辑草稿升级到 AI 精剪。

## 目标

1. 视频工厂所有生成动作都能向统一进度系统上报状态，包括文案、分镜、图片、配音、字幕、时间线、AI 剪辑决策、剪映草稿、未来 DaVinci 草稿。
2. 每个视频任务都有可恢复的运行日志，刷新页面、切换模块或重新打开软件后仍能看到最近进度。
3. UI 中固定提供总进度条、当前步骤、实时日志栏和模块内细进度，避免用户误以为软件卡死。
4. 删除任务时，任务日志和图片/音频/渲染缓存一起删除；剪映原生草稿仍由用户在剪映里自行删除。
5. 把当前基础剪辑保留为稳定默认路径，不因为引入二次精剪而破坏现有可用流程。
6. 定义统一 `Edit Decision Plan`，让二次精剪决策先落到中间格式，再由剪映优先适配器或 DaVinci 实验适配器执行。
7. 为后续自动续跑、失败重试、备用 API 切换、精剪质量检查提供统一数据基础。

## 非目标

- 不把右侧日志栏做成教程说明文档。它只显示真实运行状态和产物。
- 不在每个小卡片内重复堆日志，避免页面变乱。
- 不要求第一版就接满剪映和 DaVinci 的全部能力。
- 不绕过用户确认做发布、覆盖人工编辑、删除剪映草稿等破坏性动作。
- 不把 Codex 名称显示给普通用户。用户可见命名使用“她火自动化”“实时日志”“任务进度”“AI 精剪”。
- 不把本地大模型或 DaVinci 工程依赖打包进安装包。

## 一、实时进度控制台设计

### 信息架构

视频工厂页面增加一个全局 `任务运行控制台`。它不是一个独立页面，而是嵌在视频工厂所有模块右侧，持续显示当前任务状态。

桌面端布局：

```text
顶部模块导航
总进度条：当前任务 62% · 正在生成图片 14/24 · 预计剩余 2 分钟

左侧主操作区：主页 / 文案 / 分镜 / 素材 / 配音字幕 / 剪辑草稿 / 设置

右侧固定栏：
当前任务状态
模块细进度
实时日志
失败与待处理
授权功能折叠状态
```

右侧栏使用当前截图中“授权功能”所在列，宽度建议为 `340px` 到 `380px`。授权功能不再占据主要视觉位置，改为右侧底部折叠卡片或设置页详情。

移动或窄屏布局：

- 右侧栏收起为底部抽屉。
- 顶部仍显示总进度条和当前步骤。
- 用户点击“日志”按钮展开最近日志。

### 总进度条

总进度条放在模块导航下方，覆盖整个视频任务生命周期。它显示的是任务级进度，不是当前请求的转圈。

字段：

- 当前百分比
- 当前阶段
- 当前动作
- 当前计数，例如 `14/24`
- 最近错误数
- 暂停或等待人工确认状态

示例：

```text
总进度 62% · 素材生成 · 正在生成第 14/24 张火柴人图 · 失败 1
```

百分比采用阶段权重，不直接按日志条数计算。建议第一版权重：

| 阶段 | 权重 |
| --- | ---: |
| 来源/文案 | 15 |
| 分镜 | 15 |
| 图片/外部素材 | 25 |
| 配音/字幕 | 20 |
| 时间线 | 10 |
| 剪辑草稿 | 10 |
| 质量检查/收尾 | 5 |

如果用户跳过某阶段，例如直接粘贴文案，则该阶段视为完成但日志需要记录“用户跳过模型生成，使用原文直通”。

### 模块细进度

每个模块内部顶部保留一条轻量细进度，显示当前模块的局部状态。

文案页：

```text
文案生成：分析结构 → 改写 → 风险降级 → 保存结果
```

分镜页：

```text
分镜生成：已生成 18 条 · 目标时长 60 秒 · 待人工调整 0
```

素材页：

```text
图片生成：成功 13 · 失败 1 · 队列 10 · 并发 8
```

配音字幕页：

```text
配音：IndexTTS2 克隆中 · 字幕待对齐 · 参考音频已选择
```

剪辑草稿页：

```text
剪辑：AI 精剪决策生成中 → 写入剪映草稿 → 验证轨道
```

### 右侧实时日志栏

右侧日志栏是核心视图。它显示最近 200 条任务日志，按时间倒序或顺序可切换，默认顺序为从早到晚，最新日志自动滚到底部。

日志条目展示：

- 时间，精确到秒
- 阶段标签
- 状态图标或短标签
- 一句话说明
- 可选产物路径
- 可选错误原因和下一步处理

状态类型：

- `queued`：已排队
- `running`：进行中
- `success`：完成
- `retrying`：失败后重试
- `fallback`：切换备用 API 或备用引擎
- `warning`：有风险但可继续
- `failed`：失败并暂停
- `needs_manual`：需要人工确认
- `artifact`：产物已保存

示例：

```text
15:32:10 文案 running 正在请求文本模型 rewrite_b
15:32:22 文案 success 文案生成完成，已保存 1280 字
15:32:23 分镜 running 正在拆分镜，目标时长 60 秒
15:32:31 图片 running 正在生成第 1/24 张火柴人图
15:32:49 图片 artifact 已保存 shot_01_stickman.png
15:33:02 图片 fallback 主接口余额不足，切换备用图片 API
15:34:40 配音 running IndexTTS2 正在用参考音频克隆解说
15:35:12 剪辑 artifact 剪映草稿已写入 D:\剪映草稿\JianyingPro Drafts\...
```

### 数据结构

前端 React 状态只负责实时展示，不作为唯一事实来源。每个任务需要持久化日志。

建议文件：

```text
%APPDATA%\她火\tasks\<taskId>\run_logs\progress.jsonl
%APPDATA%\她火\tasks\<taskId>\run_logs\progress-summary.json
```

`progress.jsonl` 每行一条事件：

```json
{"id":"evt_20260619_153210_001","taskId":"video_20260619153210","at":"2026-06-19T15:32:10.000+08:00","stage":"script","state":"running","message":"正在请求文本模型 rewrite_b","current":0,"total":1,"progress":0.12}
```

`progress-summary.json` 保存最新汇总，方便快速恢复 UI：

```json
{
  "taskId": "video_20260619153210",
  "state": "running",
  "stage": "images",
  "message": "正在生成第 14/24 张火柴人图",
  "progress": 0.62,
  "current": 14,
  "total": 24,
  "successCount": 13,
  "failureCount": 1,
  "needsManual": false,
  "updatedAt": "2026-06-19T15:40:00.000+08:00"
}
```

任务快照仍保存在现有 `VideoTaskSnapshot` 体系中；运行日志保存到任务目录。删除任务时，现有任务缓存删除机制会连同 `run_logs` 一起删除，剪映原生草稿不受影响。

### 前端接口

新增任务进度领域模型：

```ts
type VideoTaskRunStage =
  | "source"
  | "script"
  | "storyboard"
  | "images"
  | "voice"
  | "subtitles"
  | "timeline"
  | "edit_decision"
  | "draft"
  | "quality_check"
  | "publish"

type VideoTaskRunState =
  | "queued"
  | "running"
  | "success"
  | "retrying"
  | "fallback"
  | "warning"
  | "failed"
  | "needs_manual"
  | "artifact"

type VideoTaskRunEvent = {
  id: string
  taskId: string
  at: string
  stage: VideoTaskRunStage
  state: VideoTaskRunState
  message: string
  current?: number
  total?: number
  progress?: number
  artifact?: {
    kind: string
    path: string
    label: string
  }
  error?: {
    code: string
    message: string
    retryable: boolean
  }
}
```

新增前端组件：

- `TaskProgressHeader`：总进度条。
- `TaskRunConsole`：右侧日志栏。
- `ModuleProgressStrip`：模块内部细进度。
- `TaskRunEventList`：日志列表。
- `TaskRunFailurePanel`：失败与待处理入口。

### Electron 接口

桌面端新增 IPC：

- `ta-huo:append-task-run-event`
- `ta-huo:read-task-run-events`
- `ta-huo:read-task-run-summary`
- `ta-huo:clear-task-run-log`

写入时必须限制路径在：

```text
app.getPath("userData")\tasks\<taskId>\run_logs
```

任务 ID 不能允许路径穿越。规则与任务缓存删除一致，非法任务 ID 直接拒绝。

### 生成流程接入

所有长耗时动作必须调用统一上报函数：

```ts
reportTaskProgress({
  taskId,
  stage: "images",
  state: "running",
  message: "正在生成第 3/24 张火柴人图",
  current: 3,
  total: 24,
})
```

第一版接入范围：

1. 文案生成开始、成功、失败、备用 API。
2. 分镜生成开始、成功、失败。
3. 图片队列排队、单张开始、单张成功、单张失败、重试、停止。
4. 本地 IndexTTS2 检测、合成开始、合成成功、合成失败。
5. 字幕对齐开始、成功。
6. 时间线组装开始、成功。
7. AI 剪辑决策生成开始、成功、失败。
8. 剪映草稿写入开始、成功、路径、失败。
9. 质量检查开始、发现问题、通过。

### 错误和暂停设计

错误日志必须告诉用户下一步发生什么：

- 可重试错误：显示“准备重试第 2/3 次”。
- 可切备用错误：显示“主接口失败，切换备用接口”。
- 不可恢复错误：显示“已暂停，需要处理 API Key / 素材缺失 / 本地 TTS 路径”。
- 人工确认：显示“等待确认：是否覆盖旧草稿 / 是否删除缓存 / 是否发布”。

右侧日志栏顶部需要显示当前阻塞项，不让用户翻日志找原因。

## 二、三层剪辑架构

### 总体原则

当前系统必须继续以稳定剪映草稿为默认产物。二次精剪不能直接取代基础剪辑，而是作为基础剪辑之后的增强步骤。

建议架构：

```text
基础剪辑层
  ↓ 产出基础时间线 Basic Timeline
二次加工层
  ↓ 产出统一 Edit Decision Plan
引擎适配层
  ↓ 剪映草稿 / DaVinci 工程 / 内置预览 MP4
```

### 基础剪辑层

基础剪辑层继续使用现有逻辑：

- 输入：文案、分镜、图片/外部素材、克隆配音、字幕。
- 输出：统一时间线和剪映可编辑草稿。
- 能力：画面、音频、字幕基础对齐；按分镜排素材；写入剪映草稿；轨道验证。

基础剪辑层的目标是稳定，不追求复杂特效。任何任务都应该能在基础剪辑层落地，即使二次加工层不可用。

基础剪辑层必须保证：

1. 至少一个视频轨。
2. 有配音时必须有音频轨。
3. 字幕不包含画面描述。
4. 画布比例跟任务设置一致，例如 16:9 为 1920x1080。
5. 剪映原生草稿能被剪映打开继续编辑。

### 二次加工层

二次加工层新增“精剪决策模型”。它不直接写剪映或 DaVinci，而是读取基础时间线、脚本、字幕、素材信息和目标风格，输出统一 `Edit Decision Plan`。

`Edit Decision Plan` 包含：

- 节奏策略：哪些句子快切、慢切、停顿、加强。
- 镜头运动：推、拉、轻微摇移、快速缩放、定格、轻微抖动。
- 转场策略：硬切、闪白、推拉、擦除、速度线、黑场。
- 字幕强调：关键词放大、变色、弹出、逐字、描边、位置变化。
- 音频处理：BGM ducking、音效点、静音、重音、转场音。
- 画面补强：需要补 B-roll、重复利用已有素材、插入品牌贴片或工具展示。
- 质量检查：空镜、黑屏、字幕错位、音频超出、画面比例错误、素材缺失。

示例结构：

```json
{
  "version": 1,
  "taskId": "video_20260619153210",
  "style": "stickman_fast_cut",
  "targetEngine": "jianying",
  "timelineDurationMs": 60000,
  "decisions": [
    {
      "id": "decision_001",
      "shotId": "shot_01",
      "timeRange": { "startMs": 0, "endMs": 2800 },
      "pace": "fast",
      "visualMotion": [
        { "type": "zoom_in", "from": 1.0, "to": 1.08, "easing": "easeOut" }
      ],
      "subtitleEmphasis": [
        { "text": "一晚上搞定", "style": "pop", "color": "accent" }
      ],
      "audioCues": [
        { "type": "hit", "atMs": 600, "label": "impact_light" }
      ],
      "transitionOut": { "type": "hard_cut", "durationMs": 0 }
    }
  ],
  "qualityChecks": [
    { "type": "subtitle_sync", "state": "pass" },
    { "type": "blank_visual", "state": "pass" }
  ]
}
```

### 二次加工模型输入

精剪决策模型输入必须包含足够上下文，但不能泄露 API Key。

输入字段：

- 最终解说文案。
- 字幕 cues 和时间。
- 分镜列表。
- 每个素材的类型、比例、时长、标签、是否锁定。
- 当前基础时间线。
- 目标画幅。
- 视频风格，例如火柴人、工具展示、漫剧口播。
- 用户锁定项，例如某个镜头不可改、某个字幕不可动。
- 引擎能力声明，例如剪映适配器支持哪些效果，DaVinci 适配器支持哪些效果。

模型输出必须经过 schema 校验。非法输出不能直接写入草稿，必须回退到基础剪辑层。

### 引擎适配层

引擎适配层负责把统一 `Edit Decision Plan` 转换为具体项目。

#### 剪映优先适配器

剪映适合短视频生态，默认优先使用。

第一阶段支持：

- 轨道顺序。
- 图片/视频 clip 排布。
- 音频和字幕对齐。
- 简单转场。
- 基础缩放/移动关键帧。
- 字幕强调样式。
- 品牌贴片。

后续增强：

- 常用贴纸。
- 模板化字幕。
- 卡点音效。
- 复杂动效。
- 已有剪映草稿二次写入。

风险：

- 剪映草稿协议非官方，版本变化可能导致字段失效。
- 部分高级效果需要素材 ID 或本地资源库映射。
- 必须保留草稿结构验证，不能只相信写入成功。

#### DaVinci 实验适配器

DaVinci 适合专业精剪、调色、关键帧、音频处理和批量导出，但本地环境门槛更高。

第一阶段支持：

- 读取统一 `Edit Decision Plan`。
- 创建 timeline。
- 导入素材。
- 放置视频、音频、字幕。
- 基础 transform 关键帧。
- BGM ducking 和基础音量曲线。
- 导出工程或渲染测试片。

后续增强：

- Fusion 标题和动态图形。
- 更复杂转场。
- 调色预设。
- 批量队列。
- 自动质检渲染帧。

风险：

- 用户电脑必须安装 DaVinci Resolve。
- Python API 版本和 Resolve 版本差异较大。
- Headless 能力有限，很多操作仍依赖 GUI 环境。

#### 内置预览适配器

内置 FFmpeg/预览渲染只作为兜底和质检，不作为最终精剪主引擎。

用途：

- 快速生成低清预览。
- 验证黑屏、空镜、字幕越界。
- 给用户看大致节奏。

不承担：

- 完整剪映效果复刻。
- DaVinci 专业精剪替代。

### 质量检查

二次加工完成后必须跑质量检查，结果写入实时日志。

检查项：

1. 是否有视频轨。
2. 是否有音频轨。
3. 字幕是否和解说音频数量/时长大致对齐。
4. 是否存在超过 500ms 的空画面。
5. 是否存在素材文件丢失。
6. 是否存在画布比例和素材比例严重不匹配。
7. 是否把画面描述写成字幕。
8. 是否有字幕超出画面安全区。
9. 是否有音频超过 timeline 结尾。
10. 是否有 AI 决策引用不存在的 shotId 或 assetId。

检查失败时不直接覆盖成功草稿。系统应生成问题日志，并允许用户回退到基础剪辑草稿。

## 三、实施阶段建议

### 阶段 A：实时进度控制台基础版

目标：让用户能看到软件正在做什么。

范围：

- 新增任务运行日志模型。
- Electron 写入/读取 JSONL 日志。
- 右侧固定日志栏。
- 顶部总进度条。
- 接入文案、图片、TTS、剪映草稿四条主链路。
- 删除任务时日志随任务缓存删除。

验收：

- 创建任务后，右侧能看到运行日志。
- 刷新或重启软件后能恢复最近日志。
- 图片生成队列显示 `当前/总数`。
- TTS 合成显示开始、成功、失败。
- 剪映草稿成功时显示路径。

### 阶段 B：二次加工层与引擎适配层基础版

目标：先把二次加工层和引擎适配层做扎实。B 阶段不是主页全自动，也不是单纯日志增强；它解决的是“AI 怎么做精剪决策”和“这些决策怎么落到剪映 / DaVinci 这类引擎里”。

范围：

- 二次加工层：新增“精剪决策模型”，输入基础时间线、字幕、分镜、素材和风格，输出统一 `EditDecisionPlan`。
- `EditDecisionPlan` 必须覆盖：哪些句子快切/慢切，哪些镜头推拉摇移/缩放，哪里加转场、音效和 BGM 压低，哪些字幕强调、放大、变色，哪些画面需要补 B-roll 或重复利用。
- 统一中间格式：AI 不直接写剪映或 DaVinci，而是先写通用剪辑决策，再由引擎适配器转换。
- 引擎适配层：剪映优先适配器先落地，负责把 EDP 转成可编辑剪映草稿。
- DaVinci 实验适配器作为 B 阶段接口和能力探测目标，适合专业精剪、调色、音频、关键帧、批量导出；未安装 DaVinci 时不能影响剪映默认路径。
- 基础时间线转换为初始 EDP，作为模型失败或未启用精剪时的回退。
- 至少落地缩放/移动、转场、字幕强调三类精剪决策。
- 最后做一次节奏、空镜、黑屏、字幕错位、视频轨、音频轨、素材缺失、画幅比例和画面描述误入字幕检查。
- 失败时回退基础剪辑，不破坏已经可用的剪映草稿。

验收：

- 无 AI 精剪时仍能生成基础剪映草稿。
- 有 AI 精剪时能写入至少快慢节奏、缩放/移动、转场/音效、字幕强调四类决策中的三类。
- 非法模型输出不会破坏草稿，必须回退基础剪辑。
- 剪映能正常打开生成的可编辑草稿。
- DaVinci 未安装或接口不可用时，只写实验能力状态，不阻断剪映流程。
- 字幕和配音仍然对齐，画面描述不会进入字幕轨。
- 质量检查失败时写入日志，并保留可回退的基础草稿。

### 阶段 C：主页执行中枢与一键全自动编排器

前置条件：阶段 B 必须先完成并验收。阶段 C 依赖阶段 B 的二次加工层和引擎适配层可用，包括基础时间线、配音字幕、AI 精剪决策、剪映适配器、DaVinci 实验能力状态和质量检查；如果 B 没完成，不允许直接实现一键全自动，否则按钮只会把一堆未稳定的步骤串起来。

目标：把当前“各页面分别点按钮”的流程收束到主页执行中枢。阶段 C 不是只加一个按钮，而是新增一个能被日志系统追踪、能从中断处继续、能只补失败项的全流程编排器。

#### 主页命名与信息架构

导航入口推荐命名为“主页”，页面标题可用“生产主页”。不建议继续叫“任务总览”，因为后续这个页面不只是看状态，而是任务执行入口。

当前截图里的九宫格状态卡价值有限，容易占据主操作区空间。阶段 C 应把它压缩成一条“管线状态列表”或“步骤进度列”，只显示每步的完成、失败、待处理状态；主视觉空间留给三个动作：

- `一键全自动生成`
- `从当前步骤继续`
- `只补失败项`

主页不再把每个阶段做成同权重大卡片。阶段详情、错误、产物路径交给右侧任务运行控制台和失败面板显示；主页只负责“我现在能按什么、会从哪一步开始、是否会覆盖已有成果”。

#### 文案页命名

阶段 C 需要同步消除“全自动”歧义。文案页内部的模式命名改为：

- `手动文案`：用户粘贴或编辑文案，可选择原文直通或局部改写。
- `自动文案`：根据主题、原文或来源信息调用文本模型生成/改写文案。
- `原文直通`：保留为文案处理通道，表示不调用文本模型、不改写，直接进入分镜。

文案页不再使用 `半自动` / `全自动` 作为可见标签。原因是文案页的“自动文案”只解决文案生成，不等于整条视频链路全自动；真正的“一键全自动生成”只出现在主页执行中枢。

#### 一键全自动编排器

阶段 C 新增独立的全自动编排器，不复用文案页的 `full_auto` 命名。编排器按任务当前状态选择入口，支持三类输入：

1. 粘贴完整文案。
2. 输入主题或产品方向。
3. 填入视频链接。

全自动管线：

```text
粘贴文案 / 输入主题 / 视频链接
→ 自动生成文案
→ 自动拆分镜
→ 自动生成图片
→ 自动克隆配音
→ 自动生成字幕
→ 自动组时间线
→ 自动生成 AI 剪辑决策
→ 自动导入剪映草稿
```

关键规则：

- 每一步都必须写入阶段 A 已有的实时日志和摘要，不允许静默执行；涉及剪辑决策和草稿写入的步骤必须复用阶段 B 的剪辑/精剪能力。
- 每一步都必须检查前一步产物，不允许靠 React state 异步更新“猜测已经完成”。
- 已成功产物默认保留，不覆盖；除非用户明确选择重新生成。
- 视频链接解析如果当时还没有真实接入，必须记录 `needs_manual`，提示“视频链接解析尚未接入，请改用粘贴文案或输入主题”，不能假装已经解析。
- 本地 IndexTTS2 缺少参考音频时，必须暂停并记录 `needs_manual`，不能生成无声草稿冒充完整流程。
- 剪映草稿写入成功后，日志必须显示原生草稿路径；删除任务仍然不能删除剪映原生草稿目录。

#### 从当前步骤继续

`从当前步骤继续` 用于中断或关闭软件后恢复生产。它读取任务快照、运行日志摘要和失败面板，找到第一个未完成或需要重跑的阶段。

继续规则：

- 已有文案则跳过文案生成。
- 已有分镜则跳过拆分镜。
- 已有对应分镜图片则跳过图片生成。
- 已有真实配音和字幕则跳过配音字幕。
- 已有时间线则跳过时间线组装。
- 已有 AI 剪辑决策则跳过精剪决策。
- 已有可用剪映草稿则不重复导入，除非用户明确选择重新导入。

继续时必须在日志开头写一条恢复摘要，例如：

```text
恢复任务：跳过文案、分镜、12 张已完成图片；从图片 13/24 继续。
```

#### 只补失败项

`只补失败项` 用于失败修复，不是重新跑全流程。它只处理日志和快照里明确失败或缺失的产物。

第一版可覆盖：

- 图片生成失败的分镜。
- 缺少配音文件或 TTS 合成失败。
- 字幕缺失或字幕数量明显不匹配。
- 时间线缺失。
- AI 剪辑决策失败。
- 剪映草稿写入失败。

不可自动判断的情况必须转成 `needs_manual`，例如 API 余额不足、参考音频缺失、素材文件在磁盘上被用户移动。

#### 调用阶段 B 的二次加工层和引擎适配层

阶段 C 不重新定义 `EditDecisionPlan`，也不在主页里直接写剪映或 DaVinci 协议。主页全自动编排器只负责按顺序调用阶段 B 已经完成的二次加工层和引擎适配层：

- 时间线完成后调用阶段 B 的 EDP 生成能力。
- EDP 校验通过后调用阶段 B 的剪映适配器。
- EDP 或剪映写入失败时调用阶段 B 的基础剪辑回退路径。
- 质量检查结果回写到阶段 A 的运行日志。

验收：

- 阶段 A 的实时日志基础已经通过验收，阶段 B 的二次加工层和引擎适配层已经通过验收。
- 主页显示 `一键全自动生成`、`从当前步骤继续`、`只补失败项`，并能说明下一步从哪里开始。
- 文案页显示 `手动文案`、`自动文案`、`原文直通`，不再用 `半自动` / `全自动` 造成歧义。
- 无 AI 精剪时仍能生成基础剪映草稿。
- 有 AI 精剪时能写入至少缩放、转场、字幕强调三类决策。
- 非法模型输出不会破坏草稿。
- 全自动过程中任一步失败，都能在右侧日志和失败面板看到原因与下一步。
- `从当前步骤继续` 不重复覆盖已成功产物。
- `只补失败项` 不重新生成已经成功的图片、配音和剪映草稿。

### 阶段 D：剪映精剪增强

目标：让剪映草稿具备明显二次加工效果。

范围：

- 关键帧缩放/移动。
- 字幕关键词强调。
- 转场和音效点。
- BGM ducking。
- 素材复用和补 B-roll 提示。
- 草稿结构验证。

验收：

- 同一文案生成的精剪草稿明显区别于基础草稿。
- 剪映能正常打开编辑。
- 字幕和音频仍对齐。

### 阶段 E：DaVinci 实验适配器

目标：验证 DaVinci 是否适合作为专业精剪出口。

范围：

- 检测 DaVinci 安装和 Python API。
- 从 EDP 创建 Resolve timeline。
- 导入素材和基础轨道。
- 写入 transform/音量关键帧。
- 输出实验工程。

验收：

- 未安装 DaVinci 时不影响剪映流程。
- 安装 DaVinci 时能创建测试工程。
- 失败日志写入进度控制台。

## 四、UI 细节要求

### 右侧栏

右侧栏保持工作台风格，避免花哨装饰。

结构：

1. 当前任务卡：标题、状态、总进度。
2. 当前动作卡：阶段、动作、计数。
3. 实时日志：可滚动列表。
4. 失败与待处理：只在有问题时展开。
5. 授权功能：折叠显示。

日志列表高度应填满右侧剩余空间，避免右侧出现多个同权重卡片挤压。

### UI 冲突优先级

如果实时进度控制台和现有 UI 发生空间、层级或注意力冲突，优先保证日志和进度可见。原因是自动生成过程中，用户最需要知道软件正在做什么、是否失败、是否需要人工处理。

冲突处理规则：

1. 日志栏优先级高于授权功能、说明文字、辅助提示和低频设置入口。
2. 右侧空间不足时，先折叠授权功能和说明卡片，再压缩日志栏。
3. 主操作区和日志栏冲突时，保留顶部总进度条和至少最近 5 条日志可见。
4. 不允许把日志挤到页面底部导致用户需要滚动很久才能看到。
5. 窄屏下日志可以变成底部抽屉，但顶部必须保留当前阶段和总进度。
6. 长错误、长路径和模型返回信息必须换行或折叠，不能撑破布局。
7. 当任务运行中，日志栏的视觉权重高于静态配置区；当任务空闲时，静态配置区可以恢复正常权重。

这条规则适用于后续所有视频工厂模块：文案、分镜、素材、配音字幕、剪辑草稿和设置页。任何新增 UI 如果会遮挡或挤压进度显示，都应先重新布局，而不是牺牲日志可见性。

### 颜色与状态

状态颜色必须克制：

- running：前景色或轻蓝。
- success：绿色。
- warning/retrying/fallback：黄色。
- failed：红色。
- needs_manual：橙色。
- artifact：青绿色。

不要使用大面积高饱和背景。日志栏主要靠标签、图标和文字层级表达状态。

### 空状态

没有任务时：

```text
暂无运行日志
新建任务后，这里会显示文案、图片、配音和剪辑草稿的实时进度。
```

任务已完成时：

```text
任务完成
最新产物：剪映草稿路径
```

任务失败时：

```text
任务已暂停
原因：图片接口余额不足，且没有可用备用接口
下一步：到设置页配置备用图片 API 后继续
```

## 五、数据保留与清理

任务目录结构：

```text
%APPDATA%\她火\tasks\<taskId>\
  stickman_image\
  voice_audio\
  rendered_video\
  jianying_drafts\
  run_logs\
    progress.jsonl
    progress-summary.json
```

删除任务时删除整个任务目录，因此日志、图片、音频、预览渲染、任务内剪映草稿包都会删除。

不删除：

```text
D:\剪映草稿\JianyingPro Drafts
D:\剪映草稿\JianyingPro Materials
```

这两个目录由用户在剪映内自行管理。

## 七、完成定义

实时进度控制台完成定义：

- 用户在任意模块都能看到当前任务总进度和实时日志。
- 所有主生成链路都有开始、成功、失败日志。
- 日志可恢复，重启软件后不丢最近记录。
- 失败时用户能看到明确原因和下一步。
- 删除任务会删除日志和缓存，不删除剪映原生草稿。

二次精剪架构完成定义：

- 基础剪辑层仍可稳定生成剪映可编辑草稿。
- AI 精剪输出统一 `Edit Decision Plan`，不直接绑死剪映或 DaVinci。
- 剪映适配器能消费 EDP 并生成带基础精剪效果的草稿。
- DaVinci 适配器作为实验能力，不影响剪映默认路径。
- 质量检查能阻止明显坏草稿覆盖成功结果。

## 八、后续扩展

后续可以把这套运行控制台抽象成她火全局自动化能力，不只服务视频工厂，也服务图片工作台、批量矩阵和发布队列。

当该机制稳定后，可以再抽成一个 Codex skill 或项目内脚手架，用于后续所有长任务：

- 新功能必须定义进度事件。
- 长耗时动作必须写日志。
- 任务删除必须清理对应日志。
- 完成后把最终摘要写入任务记录。

当前阶段先在项目内实现，不急于抽成通用 skill，避免提前抽象。
